# Roadmap P0–P3 — INGLY OS SaaS

**Data:** 2026-10-11 · Target: `saas-source/INGLY-OS_14.html` (OS v96) + `saas-source/INGLY-CLOUD-ADMIN_11.html`
Principio: prima **stabilità e sicurezza**, poi **sincronizzazione e workflow ERP**, infine **funzioni evolutive** (command §finale).

## P0 — Sicurezza, integrità, processo (prima di qualsiasi feature commerciale)
- **P0-A (fatto in questa iterazione):** harness di verifica monolite + secret-scan guardrail (SEC-5/FG-11). Non distruttivo, testabile senza credenziali.
- **P0-B:** inventario e classificazione dei 505+23 `catch(){}` vuoti per categoria (SEC-4/FG-5); poi correzione **incrementale e testata** per categoria (scrittura IDB, fetch, parse). No rimozione meccanica.
- **P0-C (bloccato credenziali):** Supabase Auth reale + modello tenant + RLS per-tenant con **test negativi d'isolamento** (SEC-1/3, FG-2/3). Progettazione + adapter + test mock ora; verifica reale al rilascio credenziali.
- **P0-D:** gestione errori persistenza — un errore di scrittura deve essere registrato, restituito, mostrato, impedire conferma e consentire retry (command §5.4).

## P1 — Sincronizzazione + dominio ERP + Admin + Billing
- Backend unico fonte autorevole; IDB come cache offline + coda sync idempotente, versioning record, risoluzione conflitti (FG-1).
- Costing engine centralizzato riusato da catalogo/preventivi/ordini/report (FG-6); calcolo materiali/macchina/lavoro/margini/IVA configurabile.
- Workflow Lead→Cliente→Preventivo→Ordine→Produzione→QC→Spedizione→Fattura→Pagamento; conversione idempotente + snapshot prezzi (FG-7).
- Admin console reale su stesse API/stesso DB: utenti, ruoli/permessi server-side, piani (Starter/Pro/Business/Enterprise), sessioni (FG-1/9).
- Billing Stripe lato server + webhook firmati idempotenti + verifica piano/limiti server (FG-4). **Bloccato credenziali Stripe.**
- Anti-sharing/session management con segnali server-side (no solo IP/fingerprint), privacy/GDPR.
- Notification center con stati di consegna reali (FG-8). **Bloccato credenziali provider.**
- Audit log + backup verificato con prova di ripristino (FG-9/10).

## P2 — UI/UX enterprise + osservabilità
- Branding INGLY coerente, area identità unica, niente barre sovrapposte, tema chiaro/scuro, responsive, accessibilità WCAG AA.
- Logging centralizzato, tracing con correlation id, metriche (latenza API, salvataggi falliti, job falliti), senza segreti nei log.

## P3 — Funzioni evolutive
- Analytics commerciali reali, previsioni su dati verificati, ottimizzazione costi/marginalità, automazioni configurabili, white-label per piano, API esterne, team/workspace, ticketing. Solo dopo stabilità dei workflow base.
